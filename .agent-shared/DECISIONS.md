# Stable Decisions

## Boundaries

- The target directory is this repository's root; `../dufs/` is read-only.
- Deliverables are plain HTML/CSS/JavaScript — no build tools, frameworks, CDN, or runtime dependencies.
- `index.html` must preserve `__ASSETS_PREFIX__` and `__INDEX_DATA__`. All asset URLs must derive from the former.
- `?json`, `?simple`, and `?noscript` are handled server-side by dufs. The UI must not intercept or rewrite those responses.


`index.html` references only:

```html
<link rel="icon" href="__ASSETS_PREFIX__favicon.ico">
<link rel="stylesheet" href="__ASSETS_PREFIX__index.css">
<body data-assets-prefix="__ASSETS_PREFIX__">
  <template id="index-data">__INDEX_DATA__</template>
  <script type="module" src="__ASSETS_PREFIX__app.js"></script>
</body>
```

Sub-modules and CSS imports use relative URLs from the entry file. Dynamic icon URLs are generated by `assetUrl()`; hard-coding `/__dufs_v...__/` is forbidden.

Components may only reference tokens. Media query thresholds are CSS constants because custom properties cannot be used in `@media`.

## Data & URLs

- `parseIndexData()`: reads `#index-data.innerHTML`, decodes with `atob` + `TextDecoder` (UTF-8), then `JSON.parse`. Decode failure renders a fatal error; initialisation does not continue.
- `DATA.kind` can only be `Index | Edit | View`. Unknown values cause a failure shutdown.
- `baseUrl()` strips query string and hash.
- `joinEntryUrl(name, { directory })`: builds a URL relative to the current directory; each segment is `encodeURIComponent`-encoded; directories get a trailing `/`.
- `joinAbsolutePath(path)`: roots at `location.origin + DATA.uri_prefix`; encodes each segment. String concatenation that bypasses `uri_prefix` is forbidden.
- `assetUrl(path)`: `document.body.dataset.assetsPrefix + path`.
- Breadcrumbs are built from `DATA.href`; the root link is always `DATA.uri_prefix`.
- Search produces `?q=`; sorting only updates `sort/order`, preserves a valid `q`, and removes `json/simple/noscript/edit/view`.

## API

`js/core.js` is the sole owner of network and mutation logic, exporting:

```text
api.head(url)
api.put(url, body)
api.patch(url, body, range)      X-Update-Range: range
api.patchAppend(url, body)       semantic wrapper around patch(..., "append")
api.delete(url)
api.mkcol(url)
api.move(src, destination)       Destination: absolute encoded URL
api.copy(src, destination)       Destination: absolute encoded URL; files only
api.checkAuth(forceLogin=false)  CHECKAUTH; forceLogin => ?login
api.logout(user)                 XMLHttpRequest LOGOUT, preserves username parameter
api.downloadUrl(url)             authenticated: ?tokengen -> ?token; otherwise original URL
```

All mutations first call `checkAuth()` then verify 2xx; errors flow into the shared dialog/toast. HEAD is only used for overwrite confirmation and resume offset detection.

Upload concurrency is fixed at 1. First attempt uses `PUT`. On retry: HEAD first — if 200, read `content-length`; if offset < file size, use `PATCH + X-Update-Range: append + file.slice(offset)`; if 404 or no length, use PUT; if offset equals file size, treat as complete; if offset exceeds file size, prompt for overwrite confirmation then PUT. Register `beforeunload` when the queue or an upload is active on page leave.

## Permissions & Kind

| Capability | Condition |
|---|---|
| Upload, create file/folder, copy file | `allow_upload` |
| Delete | `allow_delete` |
| Move / rename | `allow_upload && allow_delete` |
| Edit entry, save existing file | `allow_upload && allow_delete` |
| Search | `allow_search` |
| Download directory as zip | `allow_archive` |
| Download file, View | Always visible |
| Login / logout | `auth`; current state determined by `user` |

- `Index`: renders the directory listing view.
- `Edit`: renders the editor shell; if `editable` is false, preview is shown for supported formats, otherwise an "editing unavailable" message is shown. Saving is still gated by upload/delete permissions.
- `View`: same viewer shell, always read-only; save/mutation actions are not shown.
- Frontend gating only improves UX; server-side status codes are the final authority on permissions.

## Entry Display

- `Dir` and `SymlinkDir` are directories; `File` and `SymlinkFile` are files.
- Directory `size` is the child entry count: `0 items`, `1 item`, `n items`; `>=1000` shows `>999 items`.
- File size uses base-1024, at most one decimal place.
- `mtime === 0` displays `—`; otherwise `new Date(mtime)`, formatted as local `YYYY-MM-DD HH:mm`.
- Dot-prefixed names use the hidden icon; `size===0` uses the empty folder icon, otherwise non-empty; symlinks get a badge.
- File-type matching is case-insensitive. Unknown extensions use the generic icon.

## Storage

IndexData has no disk usage, total capacity, or quota. Inferring capacity from visible file sizes is forbidden; hard-coding numbers from mockups is forbidden.

The component retains its position but shows "Storage unavailable" with no progress bar by default. Numeric values and ratios will only be enabled once the server provides explicit capacity fields.

## Caching

dufs returns static assets with a one-year immutable cache; the prefix only changes with the dufs version. When publishing a UI update, the entry file, CSS imports, JS imports, and dynamic icon URLs all use the same named UI version (e.g. `?ui=0.1.0`). Versioning only the entry file is not allowed. Changes must be verified under a real dufs instance to confirm query strings do not affect file parsing.
